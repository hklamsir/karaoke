# 使用說明

本文件是 Karaoke AI Subtitler（介面與命令列）的說明頁內容來源，由 `ui/pages/help.py` 讀取並渲染。
若檔案不存在，說明頁會顯示內建的簡短版本。

工具分為兩個入口：圖形介面（`run_ui.bat`）與命令列（`python main.py`）。兩者共用同一條處理管線與同一份 `*_timings.json`，因此可以交替使用。

---

# 1 · 快速上手

1. **選擇影片**：在主頁「MV 影片」欄按「選擇…」，程式會以 ffprobe 讀取解析度與時長。
2. **設定屬性**：選擇語言（預設為「粵語／中文」）、輸出資料夾，以及字幕樣式（字型、字級、三種顏色、底部留白）。
3. **開始生成**：按「▶ 開始生成」。流程分為五個階段（抽取音訊、上傳、語音辨識、斷句、渲染），每階段狀態會逐一更新。上傳階段耗時 3 秒至 3 分鐘屬正常範圍，視網路狀況而定。
4. **校對字幕**：完成後按「立即開啟編輯器」，在時間軸上調整時間、修正錯字、執行斷句與合併。
5. **燒錄影片**：於編輯器工具列按「🔥 燒錄」，程式會先依主頁樣式重新產生 `.ass`，再以 ffmpeg 輸出 mp4。

# 2 · 介面導覽

## 主頁

- **基本**：影片選擇（可清除或重選）、語言提示、輸出資料夾，以及「開啟現有」`*_timings.json`（無須重跑語音辨識）。
- **樣式**：字型、字級、已唱色／未唱色／描邊色（色塊與十六進位值雙向同步）、描邊粗細、對齊方式、底部留白。
  - **底部留白**：滑桿與精確 px 數字框雙向同步（0–1000；`0` = 按畫面高度自動，1080p 約 59px）。這裡的 px 就是成品影片的像素，可直接對照 MV 內嵌字幕的位置。
  - **提前顯示**（ADR-031）：每句歌詞最多提早幾多毫秒出現，預設 3000。長間奏期間唔會再提早幾十秒見到下一句；設 `0` 即回到舊行為。
  - **倒數圓點**（ADR-031）：由空白段進入歌詞前 1.5 秒，歌詞上方會逐點亮起 3 個「●」（每 0.5 秒一點，用唱過色），開唱一刻消失。密麻麻的句子（上一句一走下一句即到）不會出圓點。
  - **換行延遲**：提前顯示開啟時等於**句尾停留** —— 最後一個字唱完後畫面多留幾多毫秒才清空（預設 1000），但不會拖過下一句開唱。
  - **主頁樣式為燒錄的權威來源**（ADR-015）：燒錄時一律套用此處設定，並寫回 `*_timings.json`；開啟舊檔時主頁會自動載入該檔樣式，兩邊維持一致。調整後會自動記錄於 `~/.karaoke/settings.json`。
- **進階**（預設收合）：保留標點、每行字數上限、停頓門檻、短句門檻（字數與時長）、合併字數上限、句尾停留、人聲分離、儲存辨識原始 JSON、辨識模型。
- **即時預覽**：任何樣式參數變更都會立即重繪（以系統字型渲染，並非 libass 逐像素輸出，因此與最終燒錄結果可能有細微差異）。
- **進度**：五階段狀態標籤與可展開的日誌窗。

## 編輯器

- **歌詞樹**（左上）：一句一行；橙色表示該行含有估算時間的字；雙擊可跳到該句開始時間；選取兩行後可合併。
- **逐字微調**（左下）：顯示當前行每個字的開始與結束時間，以**時間碼**呈現（`3:41.995` = 3 分 41.995 秒）。支援多選、± 平移、跨字均分與一鍵修補（見下表）。
- **預覽窗**（右上）：畫面疊加字幕（即時反映位置、字級、顏色、提前顯示與倒數圓點）、當前行字幕卡，以及 2 fps 縮圖捲軸（點擊可跳轉）。
  - **解析度**（ADR-032）：跟原片（= 輸出影片的真實解析度）／1920×1080／1280×720／854×480／自訂，可自行輸入闊×高。
  - **縮放**：適合視窗／50%／100%。選「跟原片 + 100%」就是 1:1 真實像素檢視；窗格不夠大時會自動降到適合視窗，狀態列會顯示**實際**百分比。
  - 縮圖只有 160px 闊，100% 縮放時背景畫面會偏模糊（字幕文字仍然清晰）；要像素級確認請按「高清單幀」。
- **時間軸**（右下）：波形、逐字方塊、播放頭與全片概覽條；上方分隔條可拖曳調整預覽與時間軸的比例。
- **燒錄**（工具列「🔥 燒錄」）：先彈出「燒錄設定」——預設用原片；若你已自行準備去人聲的**純音樂 MV**，可按「選擇純音樂 MV…」換成它，字幕會燒在該檔上面。對話框會比對時長與畫面比例並提出預警（時長相差超過 1.5 秒、比例不同），揀到沒有畫面的音檔（mp3 / wav）會直接禁用「開始燒錄」。確認後自動 render 最新 `.ass` 再燒錄，進度窗日誌預設展開；上次的資料夾會記住。

### 時間軸操作

| 操作 | 行為 |
|---|---|
| 滾輪 | 以游標位置為中心縮放（四級：0.25× / 1× / 4× / 16×） |
| Shift + 滾輪 | 水平捲動 |
| 拖曳底部藍色概覽條 | 水平平移（等同快速跳到某段） |

### 逐字微調操作

| 操作 | 行為 |
|---|---|
| 開始／結束欄填數 → Enter | 接受 `3:41.995`、`3:41`、`221.995`（秒）、`221995`（毫秒）四種寫法；Esc 取消 |
| 時間欄右邊 ▲／▼ | 每次 ±10ms，**即時生效**（改的是這一邊，即拉長／縮短；連撳合併成一個 undo） |
| `連動`（平移列右邊） | 開：改時間撞到旁邊的字時，自動把後面（或前面）整段推開，字距不變；關：只改嗰個字，重疊會在下方提示 |
| 平移 `-100` / `-10` / `+10` / `+100` | 把選取的字整體前後移，字與字之間間隔不變 |
| `⊞ 均分` | 選 3 個字以上：**首字、末字原封不動**，只把中間的字平均攤喺兩者之間 |
| `⊞ 全段` | 選 2 個字以上：由首字開始到末字結束全部重攤 —— AI 漏字後「一堆短字 + 一個超長字」用呢個 |
| `✚ 修補` | 自動偵測本行時長崩壞並重攤（中位數 6 倍以上，或 1.5 秒以上的單字） |
| `↻ 重劃本詞` | 只重置**單一個詞**內部的逐字邊界 |

> 用 `Ctrl` / `Shift` 可以多選字。任何均分結果仍然屬於估算值，會以橙色顯示，記得試聽覆核。
> 狀態列出現 `⚠n字冇時長` 代表全片有 n 個字時長為 0 —— 通常就係 AI 漏詞的位置。
| 左鍵點擊空白處 | 定位游標並播放 |
| 拖曳字塊本體 | 整體平移該詞的所有字 |
| 拖曳字塊左右邊界 | 精調該字的開始或結束時間 |
| 拖曳空白處 | （下期功能）框選後新增歌詞行 |

## 設定

- **DashScope API Key**：優先序為 `--api-key` > 環境變數 `DASHSCOPE_API_KEY` > `.env` > `settings.json`。介面寫入的值不會覆蓋環境變數。
- **FFmpeg / FFprobe 路徑**：預設自動偵測，找不到時才需手動填寫。
- **預設資料夾**：主頁選擇影片與輸出時的起始目錄。
- **外觀**：三套主題可即時切換——淺色 Litera（白底黑字，預設）、深色 Darkly（炭灰）、深色 Superhero（深藍橙）。選擇會記錄於 `~/.karaoke/settings.json`，下次啟動沿用。
- **縮圖快取**：顯示目前佔用容量，並可一鍵清除。

# 4 · 命令列（CLI）參數參考

命令列分為三個子命令，可獨立執行，亦可與圖形介面交替使用：

- `generate`：影片 → 語音辨識 → `*_timings.json` 與 `*.ass`（不輸出影片）
- `render`：`*_timings.json` → `*.ass`（修改時間或文字後只需執行此步）
- `burn`：影片 + `*.ass` → `*.mp4`（只接受已存在的 `.ass`）

以下參數表由 argparse 動態產生（`ui/clidoc.py`），因此 `main.py` 新增參數時會自動同步，不會出現文件與程式不一致的情況。

## generate

**用途**：一次完成抽取音訊、上傳、語音辨識、斷句與渲染，產出 `*_timings.json`（唯一真源）與 `*_karaoke.ass`。

**最簡用法**：

```
python main.py generate -i "D:\Videos\MV.mp4"
```

**常用組合**（指定輸出資料夾、字級 72、底部留白 160 以避開 MV 內嵌字幕）：

```
python main.py generate -i "MV.mp4" -o "D:\out" --font-size 72 --margin-v 160
```

## render

**用途**：由 `*_timings.json` 重新產生 `.ass`。校對過時間或文字後執行此命令即可，無須重跑語音辨識。

## burn

**用途**：以 ffmpeg 將 `.ass` 燒錄進畫面並重新編碼輸出 mp4。此命令不會自動執行 render，因此燒錄前請確認 `.ass` 為最新版本（圖形介面的「🔥 燒錄」會自動先做 render）。

**換用自備的純音樂 MV（ADR-020）**：把 `-i` 指向你自己準備的去人聲版本即可，字幕時間軸仍使用原片那份 `.ass`／`timings.json`：

```
python main.py burn -i "MV_純音樂.mp4" -s "MV_karaoke.ass" -o "MV_karaoke_inst.mp4"
```

> 軟件**不會**為你去人聲（AI 分離已否決，見 ADR-020），也不會自動對齊不同剪輯版本。
> 若自備 MV 的長度與原片不同，請先在編輯器調好時間軸。

**用法**：

```
python main.py burn -i "MV.mp4" -s "MV_karaoke.ass" -o "MV_final.mp4"
```

# 5 · 資料流與檔案

```
generate（CLI 或 UI）→ *_timings.json（唯一真源）
                            │
                     [UI 校對] ← 調整時間軸 / 修正文字 / 斷句合併
                            │
render（CLI，或燒錄時自動執行）→ *_karaoke.ass（衍生物，請勿手動修改）
                            │
burn（CLI 或 UI）→ *_karaoke.mp4
```

- **timings.json 是唯一真源**：需要改時間或文字時，請改此檔或使用介面；直接改 `.ass` 會在下次 render 時被無條件覆寫。
- 三個命令可獨立執行：`render` 無須重跑語音辨識；`burn` 只讀取 `.ass`。
- 中間產物（音訊、縮圖）存放於 `~/.karaoke/` 下的快取目錄，可於設定頁清除。

# 6 · 疑難排解

**問：字幕為何沒有標點？**
答：依 ADR-013，預設會移除標點（行尾刪除、行中轉為空格並保留停頓）。若需保留，請加 `--keep-punctuation`，或在介面「進階 → 保留標點」開啟。

**問：為何仍要人工校對時間？**
答：語音辨識只提供「詞級」時間軸，多字漢語詞的逐字邊界是依字數比例估算（`estimated: true`，介面顯示橙色）。實測約 57% 的字屬於估算值，編輯器的主要功能就是校對這些字。

**問：為何每次辨識結果不同？**
答：語音辨識本身具非確定性，同一段影片兩次執行可能得到 13 句與 12 句。校對完成的 json 請務必儲存。

**問：上傳階段為何要等數分鐘？**
答：音訊需上傳至百煉臨時儲存，耗時在 3 秒至 3 分鐘之間波動，屬正常現象；此階段的進度顯示為迴圈動畫。

**問：字幕與 MV 原有內嵌字幕重疊怎麼辦？**
答：調大「底部留白」（例如 160 px）即可避開內嵌字幕，效果可在預覽窗即時確認。

**問：API Key 應放在哪裡？**
答：建議使用環境變數：`setx DASHSCOPE_API_KEY "sk-xxxx"`；亦可於設定頁填寫（存於 `~/.karaoke/settings.json`，不會納入版本控制）。

**問：燒錄後的影片完全沒有字幕？**
答：多數是 ASS 時間戳格式問題（寫成 `M:SS.cc` 會被 libass 解讀為秒數）。本工具的 `ms_to_ass_time` 已強制輸出 `H:MM:SS.cc`；若曾手動修改 `.ass`，請先檢查格式。

# 7 · 已知陷阱

| 陷阱 | 說明 |
|---|---|
| ASS 時間戳格式 | 必須為 `H:MM:SS.cc`；若寫成 `M:SS:cc`，libass 會解讀錯誤並輸出無字幕影片（ADR-005） |
| Windows 路徑冒號 | 直接把 `C:\...` 寫進 `ass=<path>` 會被視為 filter 分隔符而失敗；本工具以切換工作目錄加檔名方式解決（ADR-006） |
| `language_hints` 陷阱 | `yue` 實際是「粵語轉普通話」開關；本工具一律重映射為 `zh`（ADR-001） |
| `paraformer-v2` 假時間軸 | 其「逐字時間」為線性插值，並非真實對齊；已永久停用（ADR-004） |
| v1 舊版 json | 標點黏在 text 尾端；讀入時會自動拆出並僅記錄警告 |
| tkinter 縮圖格式 | PhotoImage 不支援 JPEG，縮圖一律輸出 PNG |
