# 使用說明

本文件是 Karaoke AI Subtitler（介面與命令列）的說明頁內容來源，由 `ui/pages/help.py` 讀取並渲染。
若檔案不存在，說明頁會顯示內建的簡短版本。

工具分為兩個入口：圖形介面（`run_ui.bat`）與命令列（`python main.py`）。兩者共用同一條處理管線與同一份 `*_timings.json`，因此可以交替使用。

---

# 1 · 快速上手

1. **選擇影片**：在主頁「MV 影片」欄按「選擇…」，程式會以 ffprobe 讀取解析度與時長。
2. **設定屬性**：選擇語言（預設為「粵語／中文」）、輸出資料夾，以及字幕樣式（字型、字級、三種顏色、底部留白）。
3. **開始生成**：按「▶ 開始生成」。流程分為五個階段（抽取音訊、上傳、語音辨識、斷句、渲染），每階段狀態會逐一更新。上傳階段耗時 3 秒至 3 分鐘屬正常範圍，視網路狀況而定；此階段沒有百分比，畫面會顯示「已等 N 秒」讓你知道程式仍在工作（ADR-048）。
4. **校對字幕**：完成後按「立即開啟編輯器」，在時間軸上調整時間、修正錯字、執行斷句與合併。
5. **燒錄影片**：於編輯器工具列按「🔥 燒錄」，程式會先依主頁樣式重新產生 `.ass`，再以 ffmpeg 輸出 mp4。

# 2 · 介面導覽

## 主頁

- **基本**：影片選擇（可清除或重選）、語言提示、輸出資料夾，以及「開啟現有」`*_timings.json`（無須重跑語音辨識）。
- **樣式**：字型、字級、已唱色／未唱色／描邊色（色塊與十六進位值雙向同步）、描邊粗細、陰影、對齊方式、底部留白。
  - **描邊粗細**（ADR-049）：下拉保留「自動／幼 2／中 3／粗 4」四個快捷值，也可以直接輸入數字（0–30px，接受一位小數）。旁邊會即時顯示「= 6.5px」；輸入無法解析時標紅提示，`0` 仍代表「按畫面高度自動」（1080p 約 3px）。描邊是絕對像素，不隨字級或解析度縮放。
  - **陰影**（ADR-050）：`px` 填 0 即關閉；填 1–30 會在字右下 45° 加陰影（與 libass 原生行為一致）。可另設陰影色（色塊或 `#RRGGBB`）與不透明度（0–100%，預設 50%）：深色 MV 建議 30–40%，淺色 MV 可提高到 70%。陰影關閉時輸出的字幕檔與舊版完全相同。
  - **底部留白**：滑桿與精確 px 數字框雙向同步（0–1000；`0` = 按畫面高度自動，1080p 約 59px）。這裡的 px 就是成品影片的像素，可直接對照 MV 內嵌字幕的位置。
  - **提前顯示**（ADR-031）：每句歌詞最多提早多少毫秒出現，預設 3000。長間奏期間不會再提早幾十秒見到下一句；設 `0` 即回到舊行為。
  - **倒數圓點**（ADR-031）：由空白段進入歌詞前 1.5 秒，**歌詞第一個字上方**會逐點亮起 3 個「●」（每 0.5 秒一點，用唱過色），開唱一刻消失；若歌詞置頂，圓點改放在行下方，同樣對齊第一個字。
  - **圓點條件**：只有「上一句結束後至少隔 N ms」（預設 5000ms，0 = 停用）的長空白才出圓點；密的句子（上一句一走下一句即到）不會出。
  - **換行延遲**：提前顯示開啟時等於**句尾停留** —— 最後一個字唱完後畫面多留多少毫秒才清空（預設 1000），但不會拖過下一句開唱。
  - **雙行歌詞**（ADR-027）：開啟後兩句同時顯示（上一句在上行、當前句在下行），適合長句或卡拉 OK 對唱。
  - **雙行行距**：以「× 字級」表示（1.00–2.50，預設 1.00）。用倍數而非 px，換字級時行距會自動跟隨。
  - **上行位置 / 下行位置**（ADR-030）：雙行模式的水平錯位（居左／居中／居右等），用來模仿 MV 原版「上偏左、下偏右」的排版。
  - **整體平移**（ADR-029）：全片時間統一前後移（±5000ms，正值 = 全部延後）。只影響 render／燒錄，不會改動 `timings.json` 內每個字的原始時間 —— 換另一版剪輯的 MV 時先用它對位。
  - **主頁樣式為燒錄的權威來源**（ADR-015）：燒錄時一律套用此處設定，並寫回 `*_timings.json`；開啟舊檔時主頁會自動載入該檔樣式，兩邊維持一致。調整後會自動記錄於 `~/.karaoke/settings.json`。
- **進階**（預設收合）：保留標點、每行字數上限（預設 18）、停頓閾值（800ms）、短句門檻（字數 5／時長 2500ms）、合併字數上限（16）、句尾停留（300ms）、人聲分離、儲存 ASR 原始 JSON、辨識模型。
  - **編輯器偏好**（同一區底部，只寫入 `~/.karaoke/settings.json`，不影響生成結果）：`插字時長`（逐字微調「+字前／+字後」新字的長度，預設 100ms）、`新增行長度`（歌詞樹插入新行的預設句長，預設 3000ms）。
- **即時預覽**：任何樣式參數變更都會立即重繪（以系統字型渲染，並非 libass 逐像素輸出，因此與最終燒錄結果可能有細微差異）。
- **進度**：五階段狀態標籤與可展開的日誌窗。

## 編輯器

- **歌詞樹**（左上）：一句一行，欄位 `#` / `歌詞` / `開始` / `結束` / `估算`（橙色 `●n` = 該行有 n 個估算時間的字）。雙擊句子會跳到該句開始時間播放；`Ctrl` / `Shift` 可多選，多選後按「🔗 合併」把數句併成一句。
  - 工具列：`✏ 修改`（改整句文字）／`+ 此行前`／`+ 此行後`／`🔗 合併`／`🗑 刪行`。
  - 右鍵選單提供同一組操作（修改目前行、前後插入、刪除此行），唔需要先準確點中工具列。
  - 新增行的時間自動塞入該行前面的空隙（無字幕區段補 AI 漏句），插入後可即時在時間軸拖曳調整；預設長度可在主頁「進階」的「新增行長度」改。
- **修改歌詞列**（左欄，按「✏ 修改」後出現）：直接在輸入框打字，`Enter` 套用、`Esc` 取消，不會另開彈窗。
- **逐字微調**（左下）：顯示當前行每個字的開始與結束時間，以**時間碼**呈現（`3:41.995` = 3 分 41.995 秒）。支援多選、± 平移、跨字均分、一鍵修補與逐字改字／加字／刪字（見下表）。
- **預覽窗**（右上）：畫面疊加字幕（即時反映位置、字級、顏色、提前顯示與倒數圓點）、當前行字幕卡，以及 2 fps 縮圖捲軸（點擊可跳轉）。
  - 右邊按鈕：`換原片…`（改燒錄目標，字幕時間軸不變）／`高清單幀`（向原片抽一張全解析度畫面）／`外部播放器`（用系統播放器開原片，對位時聽原聲最準）。
  - **解析度**（ADR-032／ADR-051）：跟原片（= 成品沿用 MV 原始解析度）／1920×1080／1280×720／854×480／自訂（可輸入闊×高）。**這就是成品解析度**：選 1920×1080 後燒錄會把畫面縮入 1920×1080 並補黑邊（不裁切），成品檔案真正是 1920×1080；字級 px 不變，所以預覽見到的大小＝成品大小。所選值會寫入 `timings.json` 的 `output_res`，重開檔案仍然記得。
  - **縮放**：適合視窗／50%／100%。選「跟原片 + 100%」就是 1:1 真實像素檢視；窗格不夠大時會自動降到適合視窗，狀態列會顯示**實際**百分比。
  - 預覽窗的成品框＝所選解析度比例，原片畫面以**完整（contain）**方式置中，黑邊闊度與 ffmpeg `pad` 一致（所以 4:3 的 MV 選 1920×1080 會見到左右黑邊，不會被拉闊）。
  - 縮圖只有 160px 闊，100% 縮放時背景畫面會偏模糊（字幕文字仍然清晰）；要像素級確認請按「高清單幀」。
- **時間軸**（右下）：波形、逐字方塊、播放頭與全片概覽條；上方分隔條可拖曳調整預覽與時間軸的比例，左邊分隔條可拖曳調整歌詞樹／逐字微調欄的闊度。
- **工具列**：`💾 儲存`、`🔥 燒錄`、`↶` / `↷`（復原／重做）、播放／下一句／重播 3 秒、`只顯示估算字`（篩走已對好時間的行）、`字幕疊圖`（開關預覽字幕）、`🎨`（快速改樣式）。
- **燒錄**（工具列「🔥 燒錄」）：先彈出「燒錄設定」——預設用原片；若你已自行準備去人聲的**純音樂 MV**，可按「選擇影片／音檔…」換成它，畫面與音軌都取自該檔，字幕燒在它上面。對話框會顯示**成品解析度**（跟燒錄來源，或你在預覽「解析度」選的尺寸，並標明縮放／補黑邊），亦會比對時長與畫面比例並提出預警（時長相差超過 1.5 秒、比例不同）。選到沒有畫面的音檔（mp3 / wav）**不會被禁用** —— 對話框下方會出現「背景」設定（ADR-039）：可用純色或自選圖片合成畫面，並選填滿（裁切）或完整（加邊）。確認後自動 render 最新 `.ass` 再燒錄，進度窗日誌預設展開；上次的資料夾會記住。

### 時間軸操作

| 操作 | 行為 |
|---|---|
| 滾輪 | 以游標位置為中心縮放（四級：0.25× / 1× / 4× / 16×） |
| Shift + 滾輪 | 水平捲動 |
| 拖曳底部藍色概覽條 | 水平平移（等同快速跳到某段） |
| 🔍－ / 🔍＋（時間軸左下） | 逐級縮小／放大 |
| 左鍵點擊空白處 | 定位游標並播放 |
| 空白處按住拖曳 | 連續 scrub：播放頭跟住滑鼠走，放開停在該處 |
| 拖曳字塊本體 | 整體平移該詞的所有字 |
| 拖曳字塊左右邊界 | 精調該字的開始或結束時間 |

> 時間軸空白處**不再**用來框選範圍新增歌詞行（ADR-051 已移除該入口）；新增行請用歌詞樹「＋ 此行前／後」或右鍵選單。

### 逐字微調操作

| 操作 | 行為 |
|---|---|
| 開始／結束欄填數 → Enter | 接受 `3:41.995`、`3:41`、`221.995`（秒）、`221995`（毫秒）四種寫法；Esc 取消 |
| 時間欄右邊 ▲／▼ | 每次 ±10ms，**即時生效**（改的是這一邊，即拉長／縮短；連撳合併成一個 undo） |
| `連動`（平移列右邊） | 開：改時間撞到旁邊的字時，自動把後面（或前面）整段推開，字距不變；關：只改那個字，重疊會在下方提示 |
| 平移 `-100` / `-10` / `+10` / `+100` | 把選取的字整體前後移，字與字之間間隔不變 |
| `✓ 確定` | 套用開始／結束欄手動輸入的值 |
| `⊞ 均分` | 選 3 個字以上：**首字、末字原封不動**，只把中間的字平均攤在兩者之間 |
| `⊞ 全段` | 選 2 個字以上：由首字開始到末字結束全部重攤 —— AI 漏字後「一堆短字 + 一個超長字」用這個 |
| `✚ 修補` | 自動偵測本行時長崩壞並重攤（中位數 6 倍以上，或 1.5 秒以上的單字） |
| `↻ 重劃` | 只重置**單一個詞**內部的逐字邊界 |
| `✂ 斷句` | 在選中字之後斷成新一行（可以斷穿一個詞） |
| `✏ 修改` | 改**選中那一個字**的文字（改整句請用歌詞樹「✏ 修改」） |
| `✕ 刪字` | 刪除選中的一個字；行只剩一個字時請改用歌詞樹「🗑 刪行」 |
| `+字前` / `+字後` | 在選中字之前／之後插入一個新字（長度 = 主頁「進階 → 插字時長」，預設 100ms） |

> 用 `Ctrl` / `Shift` 可以多選字。任何均分結果仍然屬於估算值，會以橙色顯示，記得試聽覆核。
> 狀態列出現 `⚠n字冇時長` 代表全片有 n 個字時長為 0 —— 通常就是 AI 漏詞的位置。

## 設定

- **DashScope API Key**：優先序為 `--api-key` > 環境變數 `DASHSCOPE_API_KEY` > `.env` > `settings.json`。介面寫入的值不會覆蓋環境變數；旁邊的「測試連線」會即場驗證金鑰可否用（不需要先跑一次辨識）。
- **FFmpeg / FFprobe 路徑**：預設自動偵測，找不到時才需手動填寫。使用可攜式（portable）FFmpeg 時，請填寫執行檔的完整路徑（例如 `D:\ffmpeg\bin\ffmpeg.exe` 與 `D:\ffmpeg\bin\ffprobe.exe`）；填寫後，主頁生成與編輯器燒錄都會直接使用該路徑，無須把資料夾加入 `PATH`。若填寫的路徑不存在，程式會明確提示該路徑無效，不會退回自動偵測。
- **預設資料夾**：主頁選擇影片與輸出時的起始目錄。
- **外觀**：三套主題可即時切換——淺色 Litera（白底黑字，預設）、深色 Darkly（炭灰）、深色 Superhero（深藍橙）。選擇會記錄於 `~/.karaoke/settings.json`，下次啟動沿用。
- **縮圖快取**：顯示目前佔用容量，並可一鍵清除。

# 4 · 命令列（CLI）參數參考

命令列分為三個子命令，可獨立執行，亦可與圖形介面交替使用：

- `generate`：影片 → 語音辨識 → `*_timings.json` 與 `*.ass`（不輸出影片）
- `render`：`*_timings.json` → `*.ass`（修改時間或文字後只需執行此步）
- `burn`：影片 + `*.ass` → `*.mp4`（只接受已存在的 `.ass`）

以下參數表由 argparse 動態產生（`ui/clidoc.py`），因此 `main.py` 新增參數時會自動同步，不會出現文件與程式不一致的情況。

## generate

**用途**：一次完成抽取音訊、上傳、語音辨識、斷句與渲染，產出 `*_timings.json`（唯一真源）與 `*_karaoke.ass`。

**最簡用法**：

```
python main.py generate -i "D:\Videos\MV.mp4"
```

**常用組合**（指定輸出資料夾、字級 72、底部留白 160 以避開 MV 內嵌字幕）：

```
python main.py generate -i "MV.mp4" -o "D:\out" --font-size 72 --margin-v 160
```

## render

**用途**：由 `*_timings.json` 重新產生 `.ass`。校對過時間或文字後執行此命令即可，無須重跑語音辨識。

**用法**：

```
python main.py render "MV_timings.json"
```

**只改顏色並永久寫回**（`--sync-style` 會把覆寫值寫入 timings.json，而非只影響本次輸出）：

```
python main.py render "MV_timings.json" --primary-color "#00FF88" --sync-style
```

## burn

**用途**：以 ffmpeg 將 `.ass` 燒錄進畫面並重新編碼輸出 mp4。此命令不會自動執行 render，因此燒錄前請確認 `.ass` 為最新版本（圖形介面的「🔥 燒錄」會自動先做 render）。

**換用自備的純音樂 MV（ADR-020）**：把 `-i` 指向你自己準備的去人聲版本即可，字幕時間軸仍使用原片那份 `.ass`／`timings.json`：

```
python main.py burn -i "MV_純音樂.mp4" -s "MV_karaoke.ass" -o "MV_karaoke_inst.mp4"
```

> 軟件**不會**為你去人聲（AI 分離已否決，見 ADR-020），也不會自動對齊不同剪輯版本。
> 若自備 MV 的長度與原片不同，請先在編輯器調好時間軸。

**指定成品解析度（ADR-051）**：`--out-size WxH` 會把畫面按比例縮入該尺寸並補黑邊（`scale` + `pad`，不裁切），字幕按 `.ass` 的座標系疊上。不加就沿用來源尺寸；圖形介面的「解析度」下拉已會寫入 `timings.json` 的 `output_res` 並自動套用：

```
python main.py burn -i "MV.mp4" -s "MV_karaoke.ass" --out-size 1920x1080
```

**用法**：

```
python main.py burn -i "MV.mp4" -s "MV_karaoke.ass" -o "MV_final.mp4"
```

# 5 · 資料流與檔案

```
generate（CLI 或 UI）→ *_timings.json（唯一真源）
                            │
                     [UI 校對] ← 調整時間軸 / 修正文字 / 斷句合併
                            │
render（CLI，或燒錄時自動執行）→ *_karaoke.ass（衍生物，請勿手動修改）
                            │
burn（CLI 或 UI）→ *_karaoke.mp4
```

- **timings.json 是唯一真源**：需要改時間或文字時，請改此檔或使用介面；直接改 `.ass` 會在下次 render 時被無條件覆寫。
- 三個命令可獨立執行：`render` 無須重跑語音辨識；`burn` 只讀取 `.ass`。
- 中間產物（音訊、縮圖）存放於 `~/.karaoke/` 下的快取目錄，可於設定頁清除。

# 6 · 疑難排解

**問：字幕為何沒有標點？**
答：依 ADR-013，預設會移除標點（行尾刪除、行中轉為空格並保留停頓）。若需保留，請加 `--keep-punctuation`，或在介面「進階 → 保留標點」開啟。

**問：為何仍要人工校對時間？**
答：語音辨識只提供「詞級」時間軸，多字漢語詞的逐字邊界是依字數比例估算（`estimated: true`，介面顯示橙色）。實測約 57% 的字屬於估算值，編輯器的主要功能就是校對這些字。

**問：為何每次辨識結果不同？**
答：語音辨識本身具非確定性，同一段影片兩次執行可能得到 13 句與 12 句。校對完成的 json 請務必儲存。

**問：上傳階段為何要等數分鐘？**
答：音訊需上傳至百煉臨時儲存，耗時在 3 秒至 3 分鐘之間波動，屬正常現象。此階段沒有百分比可顯示（ADR-048：SDK 上傳不提供位元組級回調），進度條為迴圈動畫，後方會顯示「已等 N 秒」；只要秒數持續增加，即代表上傳仍在進行。

**問：為何把「解析度」改成 1920×1080，燒錄出來的影片仍然是原片解析度？**
答：2026-11-17（ADR-051）之前的版本確實如此 —— 燒錄的 ffmpeg 指令只有 `ass=` 一個濾鏡，成品尺寸永遠等於來源影片，而「解析度」下拉只改字幕座標系（PlayRes）。現在已在燒錄時加入 `scale` + `pad`：選 1920×1080 就會輸出真正的 1920×1080（畫面按比例縮入框內、不足處補黑邊，不裁切），字級 px 不變，所以預覽見到的大小＝成品大小。所選值寫入 `timings.json` 的 `output_res`，重開檔案仍然記得；命令列可用 `--out-size 1920x1080`。若想回到「成品跟 MV」，把下拉選回「跟原片」。

**問：成品兩邊（或上下）有黑邊，正常嗎？**
答：正常。當「成品解析度」的比例與 MV 不同（例如 1:1 的 MV 選 16:9 的 1920×1080），畫面會以**完整（contain）**方式置中，不足處補黑邊 —— 這是刻意選擇：寧可加黑邊，也不裁走你的畫面內容。想要零黑邊，就把「解析度」選回「跟原片」，或選一個與 MV 相同比例的尺寸。

**問：字幕與 MV 原有內嵌字幕重疊怎麼辦？**
答：調大「底部留白」（例如 160 px）即可避開內嵌字幕，效果可在預覽窗即時確認。

**問：API Key 應放在哪裡？**
答：建議使用環境變數：`setx DASHSCOPE_API_KEY "sk-xxxx"`；亦可於設定頁填寫（存於 `~/.karaoke/settings.json`，不會納入版本控制）。

**問：燒錄後的影片完全沒有字幕？**
答：多數是 ASS 時間戳格式問題（寫成 `M:SS.cc` 會被 libass 解讀為秒數）。本工具的 `ms_to_ass_time` 已強制輸出 `H:MM:SS.cc`；若曾手動修改 `.ass`，請先檢查格式。

# 7 · 已知陷阱

| 陷阱 | 說明 |
|---|---|
| ASS 時間戳格式 | 必須為 `H:MM:SS.cc`；若寫成 `M:SS:cc`，libass 會解讀錯誤並輸出無字幕影片（ADR-005） |
| Windows 路徑冒號 | 直接把 `C:\...` 寫進 `ass=<path>` 會被視為 filter 分隔符而失敗；本工具以切換工作目錄加檔名方式解決（ADR-006） |
| `language_hints` 陷阱 | `yue` 實際是「粵語轉普通話」開關；本工具一律重映射為 `zh`（ADR-001） |
| `paraformer-v2` 假時間軸 | 其「逐字時間」為線性插值，並非真實對齊；已永久停用（ADR-004） |
| v1 舊版 json | 標點黏在 text 尾端；讀入時會自動拆出並僅記錄警告 |
| tkinter 縮圖格式 | PhotoImage 不支援 JPEG，縮圖一律輸出 PNG |
